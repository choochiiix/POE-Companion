# Normalized build assembly

`src/build.ts` exports `assembleBuild(BuildInput)` → `{ input, attributes, equipment, diagnostics }`. Pass `input` to `calculate`. Existing direct `CalculationInput` callers are unchanged. This is an explicit adapter contract, not automatic import of current UI saves, catalogs, modifier text or arbitrary PoB builds.

Supply base pools and attributes from the pinned class/level snapshot, before ordinary attribute bonuses. Sources can be provided through `passives`, `buffs`, `gems`, `configuration`, or `sources`; their IDs must be globally unique. Every equipment slot must be unique. Local armour/evasion/energy-shield BASE/INC/MORE effects resolve per item, then enter the global pool as flat contributions. Global effects retain their equipment source. Do not supply already locally modified defence and also local modifiers. Armour quality or other local effects must be explicitly normalized as appropriate local modifiers by a source adapter; no quality rule is guessed.

Attributes resolve from their explicit bases and source modifiers first. Ordinary bonuses reference the preserved `CalcPerform.lua`: floor(strength/2) life, strength/5 floored as increased melee physical damage, dexterity×2 accuracy, floor(dexterity/5) increased evasion, floor(intelligence/2) mana, floor(intelligence/10) increased energy shield. Final attribute values are floored for these bonuses. Strength damage requires explicit `skillTags: ['melee']` and applies only to the selected skill ID. No tag is inferred from skill names. `attributeBonuses: false` disables all ordinary attribute bonuses for a specialized adapter handling replacement keystones. This opt-out does not itself simulate any keystone.

`Modifier.notConditions` requires each listed condition to be absent; `conditions` requires all listed conditions present. Contradictory conditions reject. These are caller-supplied booleans, not a dependency solver. Attributes may not be skill-scoped. No overrides, equipment attribute requirements, passive legality, buff stacking or support compatibility are inferred here.

Every unnormalized effect must appear in its source's `unsupported` strings. Assembly returns source-tagged diagnostics, and calculation marks the result partial. Generated equipment/attribute source IDs are reserved; collisions reject during validation. Formula breakdowns preserve source IDs; equipment results separately preserve local modifier breakdowns.
