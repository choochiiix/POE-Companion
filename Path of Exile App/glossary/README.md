# Master glossary — first source snapshot

## Card integration update

The production card renderer now uses a derived index (`crafting-ui/tooltip-data.json`) built by `scripts/build-tooltip-index.py`. This is an explicit matching-policy layer over the master glossary: editorial terms, seeded technical wiki names with usable excerpts, and PoB skill descriptions qualify. Wiki excerpts keep their draft status and the bubble labels review as pending; this is not a bulk promotion to reviewed. Support names require named-skill context to avoid explaining ordinary modifier wording as a support gem. Common plurals and attribute abbreviations are explicitly indexed. Item class labels, names/flavor, source diagnostics and ordinary interface text are excluded. The master matcher continues to reject arbitrary draft entries without matching approval. Candidate audit in `resources/card-glossary-audit.json` includes every stored item modifier and skill-effect row; a row with a match may contain other unresolved phrases. Item-specific meanings and every missing term remain future editorial work.

Current snapshot: **1,541 entries**, including 494 available wiki articles (463 usable lead drafts), 822 gem records, 205 additional item-granted skill records and 20 editorial starter definitions. There are 516 cached page results in total, including missing titles. The audit covers 30,588 tooltip/stat rows; 11,884 rows contain at least one reviewed term and 18,704 contain none. These are row-presence counts, not proof of complete phrase coverage. Verification: 60 app/engine/data Node tests and 2 Python glossary tests passed, including the glossary routes, matching, provenance/hash checks and source-index integrity.

`master.json` is a versioned, software-readable compendium. It is generated by `scripts/wiki-glossary.py`; edit `reviewed.json` to add editorial definitions and matching aliases. Do not hand-edit generated entries. The prototype under `prototypes/catalogix/` is separate and contains demonstration data, not this production corpus.

Each entry has a stable namespaced ID, canonical name, aliases, kind, definition, review status, tooltip eligibility, allowed surfaces, related wiki titles, provenance and references into actual app records. `indexes.byId` maps IDs to entry positions; `indexes.byAlias` maps casefolded aliases to all candidate IDs. Duplicate names remain distinguishable, including wiki articles versus gem versus item-granted-skill records.

## Acquisition and rebuild

```powershell
# Offline rebuild from cached source, existing PoB archive and app data:
python scripts/wiki-glossary.py
# Explicit network acquisition: sequential batches of 20, half-second pause,
# descriptive User-Agent, maxlag, cached revisions; no runtime requests:
python scripts/wiki-glossary.py --download --limit 200
# Discover more linked titles appearing in actual item/skill/tree tooltip text:
python scripts/wiki-glossary.py --download --expand --limit 200
python scripts/test-glossary.py
node --test crafting-ui/test/glossary.test.mjs
```

The importer requests MediaWiki revisions directly, follows redirects, and records IDs, revision times, retrieval times and SHA-256 hashes. Sources are stored in `resources/wiki-glossary/pages/`; the earlier pilot snapshot is retained. It never executes wiki templates, embedded Lua, source code or page instructions. Templates are removed when extracting draft lead paragraphs. Template-heavy articles can have no usable draft. Network failure stops acquisition and leaves previous cached pages intact; rerun to resume. Missing-title results are cached and require deliberate deletion/update to retry later. An approved API/export route is used; no access controls are bypassed.

## Matching and review

`crafting-ui/glossary-model.js` supplies lookup, search and matching without modifying the app UI. Only entries explicitly marked `status: reviewed` and `tooltipEligible: true` can match. Matchable surfaces are item modifiers, skill tooltips and tree stats. Navigation, flavor text and arbitrary prose are not enabled. Longest overlapping aliases win; Unicode word boundaries prevent partial-word matches. Equal ambiguous matches and their overlapping fallback fragments are withheld. Optional `recordIds` limit a definition to particular source records, supporting item-specific meanings such as Nearby.

The starter reviewed entries are agent-edited paraphrases checked against cached source text, not user-approved or independently game-tested. Raw extracted wiki/gem descriptions are drafts and do not automatically enable underlining. In particular, Nearby has no universal numeric radius assigned. “Unaffected by” is sourced from the Immunity article; Fire Resistance and other resistance definitions are sourced from Resistance. Common words such as Fire, Damage, Attack and Life must not be globally linked merely because a source page or tag exists. An approved Life entry is restricted to tooltip surfaces.

App routes `/glossary-data.json` and `/glossary-model.js` expose the foundation locally. No tooltip renderer or underlining has yet been installed on existing cards or the tree. Restart the server after route changes. Existing character/equipment/tree/skill saves and unique art are untouched.

## Coverage and remaining work

`resources/glossary-coverage.json` reports source/draft/reviewed counts, references and every tag awaiting explicit definition mapping. `resources/glossary-unresolved.json` lists rows with no reviewed term and candidate item-granted skill phrases. An item row matching one term does not mean every phrase on that row is explained. All 3,250 stored unique variants are audited rather than only the current displayed variants; mastery effects and gem quality lines are included.

This is an initial compendium, not an exhaustive glossary of every PoE concept or thousands of manually reviewed articles. Remaining work includes editorial review, template/section extraction, relation disambiguation, tags-to-definitions mapping, linking granted-effect IDs to item records, item-specific mechanic exceptions, and the shared accessible hover/focus/tap renderer. PoB's local snapshot and present wiki revisions are not guaranteed to describe the same patch; provenance must stay visible. Exact numeric mechanics need patch-aware review.
