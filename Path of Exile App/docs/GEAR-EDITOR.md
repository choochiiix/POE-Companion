## Item creation and rules

The native modal selects a compatible base and item level, then searches eligible prefixes or suffixes. Every selected modifier exposes exact integer roll inputs constrained to its source ranges. Modifier names/descriptions come from the preserved local dataset; unavailable tier labels are not guessed. Unknown scaled units remain explicitly source units rather than invented percentages. Known life/mana/attribute/resistance/local-defence values have readable card labels.

`features/character/gear-model.js` replays each item through the actual crafting engine's `modPool`. This enforces domain, base tags, item level, ordered spawn/generation weights, duplicate IDs, exclusion groups and base affix caps. Every save and load revalidates exact rolls. `gear-editor.js` owns only presentation/draft/persistence; it does not duplicate eligibility logic. Base changes clear the draft's explicit affixes. Invalid item-level reductions are refused rather than silently deleting affixes. A dependent affix must be removed before the affix granting its eligibility. Only source-supported ordinary equipment is included; no bench/influence/essence/special-base extensions are implied.

The editor derives the **minimum ordinary rarity fitting the chosen affixes**: zero explicit affixes → normal; at most one prefix and one suffix → magic; otherwise rare, subject to supported rare caps (ordinarily three prefixes and three suffixes). A hybrid modifier may have multiple stat rolls but occupies one affix slot. Two prefixes already require rare despite only two mods. Adding mods does not manufacture a unique item. The editor is a deterministic manual item builder, not a claim about random currency count distributions or an exact reproduction of all possible in-game rarity histories.

## Integration and saves

Existing `poe-companion.equipment.v1` continues storing base IDs, so old equipment selections load as normal base-only cards. New `poe-companion.gear.v1` stores `{version:1,items:{slot:{baseId,itemLevel,rarity,mods:[{id,values}]}}}`. Source definitions and base data are not duplicated in saves. Validation derives rarity rather than trusting the saved label; invalid saved details are withheld while base selections remain available. Main/off-hand compatibility retains existing rules; changed/incompatible bases invalidate stale detailed items. Storage failure keeps current gear in memory with a session notice.

Calculation input merges the validated manual gear's exact rolled explicit stats with the item's base implicits (still midpoint estimates). Recognized raw life/mana/attributes/resistances and local defensive rolls feed the engine; local armour/evasion/energy-shield modifiers apply per item before global scaling. Unmapped raw stats and unsupported local weapon/special mechanics remain calculation diagnostics. Do not mistake legal affix selection for complete calculation coverage. There is no quality selector, unique editor, or character-requirement enforcement yet.

Existing Catalog/Crafting comparison/equip actions remain operational. Those external calculation-only item details remain separate; opening the manual builder starts from a base unless a validated manual item exists. Saving the manual draft replaces that slot's earlier calculation-only details; Cancel leaves them unchanged. Manual item rows take precedence during calculation and are cleared by explicit replacement/removal.
